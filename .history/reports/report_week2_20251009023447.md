```python
def create_pipeline():
    # Stage 1: Tokenization
    tokenizer = RegexTokenizer(
        inputCol="text", 
        outputCol="tokens",
        pattern="\\s+|[.,;!?()\"']"
    )
    
    # Stage 2: Stop words removal
    stop_words_remover = StopWordsRemover(
        inputCol="tokens", 
        outputCol="filtered_tokens"
    )
    
    # Stage 3: Term Frequency
    hashing_tf = HashingTF(
        inputCol="filtered_tokens", 
        outputCol="tf_features",
        numFeatures=NUM_FEATURES
    )
    
    # Stage 4: Inverse Document Frequency
    idf = IDF(
        inputCol="tf_features", 
        outputCol="features"
    )
    
    return Pipeline(stages=[tokenizer, stop_words_remover, hashing_tf, idf])
```

**Bước 4: Triển khai Vector Search với Jaccard Similarity**
```python
def vector_search(spark, query_text, documents, k=5):
    # Transform query using same pipeline
    query_vector = transform_query(query_text)
    
    # Calculate Jaccard similarity
    similarities = []
    for doc in documents:
        intersection = len(set(query_vector.indices) & set(doc.features.indices))
        union = len(set(query_vector.indices) | set(doc.features.indices))
        similarity = intersection / union if union > 0 else 0.0
        similarities.append(similarity)
    
    return sorted(similarities, reverse=True)[:k]
```

### 4.2 Vấn đề về Memory và Performance

**Khó khăn 3: Hash Collision trong HashingTF**
- **Vấn đề**: Vocabulary size (39,585) > numFeatures (20,000)
- **Consequence**: Hash collision rate 49.5%
- **Trade-offs analyzed**:
  - Tăng numFeatures → More memory, better accuracy
  - Giữ nguyên → Less memory, acceptable accuracy loss
- **Solution**: Chấp nhận 49.5% collision rate vì:
  - Performance vẫn tốt trong thực tế
  - Memory footprint hợp lý
  - Accuracy loss minimal cho use case này

**Khó khăn 4: Vector Search Performance**
- **Challenge**: Search through large document collection
- **Initial approach**: Brute force qua tất cả documents
- **Problem**: O(n) complexity, slow với large dataset
- **Solution**: 
  - Limit search scope to first 100 documents
  - Implement early stopping cho similarity threshold
  - Future: Có thể implement approximate nearest neighbor

### 4.3 Vấn đề thiết kế Algorithm

**Khó khăn 5: Lựa chọn similarity metric**
- **Options considered**:
  - Cosine similarity: Good for semantic similarity
  - Euclidean distance: Sensitive to vector magnitude
  - Jaccard similarity: Good for set overlap
- **Decision**: Chọn Jaccard vì:
  - Phù hợp với sparse TF-IDF vectors
  - Interpretable results (0-1 range)
  - Efficient computation với sparse vectors

### 4.4 Implementation challenges

**Khó khăn 6: Query preprocessing consistency**
- **Issue**: Query text cần đi qua cùng pipeline như training data
- **Solution**: Tạo reusable transform function
- **Code pattern**:
```python
def transform_query(query_text):
    # Ensure same preprocessing as training pipeline
    query_df = spark.createDataFrame([(query_text,)], ["text"])
    return fitted_pipeline.transform(query_df)
```

### 6.3 Algorithm Details
**HashingTF Configuration**:
- Hash function: MurmurHash3
- Feature space: 20,000 dimensions
- Collision handling: Additive (multiple terms mapping to same hash)

**IDF Weighting Formula**:
```
IDF(t) = log((N + 1) / (DF(t) + 1)) + 1
```
Where:
- N = total number of documents
- DF(t) = document frequency of term t

**Jaccard Similarity Formula**:
```
J(A,B) = |A ∩ B| / |A ∪ B|
```
Applied to non-zero indices của sparse vectors.
